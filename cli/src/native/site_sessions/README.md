# Browser site custody

Above: the backend identity service owns grants and sealed state; this driver adapts the admitted state to Chrome in a dedicated browser host.
Inside: attach is one-use and bound to an outstanding lazy request; capture and detach operate per offered site. State never enters a model reply, retained-result file or log.
Sideways: the agent channel transports host-only frames, the native CDP connection applies them, and model-written programs use their own scoped CDP sessions with output redaction.
Road ahead: W6 expiry, W7 read ceilings and W8 vault use the same site custody. Their authority stays in their owners; this module does not infer grants or manufacture approval.
Delete: one custody actor replaces per-operation state handling; a shared exact-value registry serves normal results and the program tunnel.

Pre-mortem: a paused navigation deadlocks behind command custody; program CDP sees daemon Fetch pauses; stored values escape through evaluation or retained files. Tests challenge these boundaries directly.

The private channel preserves agent protocol1 and now advertises `sessionCustody:4` with `maxCustodyChunkBytes:1048576`. Its existing v3 offer/attach/refuse/export/detach frames and8MiB+1024 envelope budget remain readable. Ordinary requests/replies remain2/4MiB. Negotiated uploads/exports carry canonical v1 JSON through1MiB parts, independent of total site capacity. A new backend can use an old v3 native driver; deploying this v4 driver requires the backend adapter that recognizes both revisions.

BEGIN consumes the exact current need within its existing two seconds, before authenticated document preparation. The same need owner retains channel, use/site/mode, page/offer/browser generation and real operation/grant expiry. FINISH verifies exact bytes/SHA256, canonical v1 and current bindings before importing anything. Progress idle expires after eight seconds without new bytes; duplicate parts/reads and keepalive never extend it. There is no additional whole-transfer duration or size bound. Export binds an explicit current-use expectation, including null for a new sign-in, before and after capture. State/read/part/close remain host-only and correlate by positive frame id.

One temporary-byte owner holds mode0600 task bytes, unlinked on Unix, with bounded JSON writes and buffered reads. Canonical typed state and the raw value registry remain proportional to actual site data. This is not constant total memory. The backend owns field authority, authenticated sealed storage, omission merge and custody/AAD; no format migration or additional native grant/store is introduced.

The existing Endpoint ledger is the connection/fence authority. Custody shares its current proof, so EOF invalidates an owned operation even while an ordinary step settles. The existing per-browser physical effect owner serializes import/export/clear and reproves exact use/expiry before cleanup. Incomplete import cancellation owns its applying job, waits for private-target retirement, clears partial state, then resolves document pauses. A stale need aborts its old document through the canonical Fetch owner and never erases a replacement use.

An unproved close or clear keeps the existing pause/use cleanup unsettled and marks the existing retained profile identity. Every ChromeProcess/RetainedChromeProfile/LaunchOptions/CDP clone sees that same disposition and refuses reuse/relaunch. Scoped cleanup on its owned connection can prove recovery. Only the existing last-owner temporary-directory lifecycle retires an ephemeral directory; no external/persistent profile is erased and closing Chrome alone is not an erasure receipt.

That retained profile also owns tab history custody. The CDP reader records current and recoverable frame origins before event broadcast, including cross-origin frames that are no longer visible. Fresh native targets establish history custody before their first document; first capture seeds an already-open frame tree without inventing a saved use. Capture and import freeze affected active documents before enumeration/mutation and await their resume under the same physical owner. On revocation/forget/cleanup, affected tabs navigate to blank and reset history before scoped storage clearing; their target IDs remain, and unrelated tabs keep their documents and history. Unknown adopted history refuses destructive cleanup before mutation rather than resetting every tab. The blank commit and one-entry history are actual Chrome receipts, not a command acknowledgement substituted for retirement.

The same retirement owner selects live workers by Chrome's actual complete StorageKey, including workers left by retired documents. It resolves namespaces before document mutation and includes workers started during pagehide. Shared/service workers close through Chrome; dedicated execution can outlive document retirement, so its current target/key-bound session requests the standard worker close. Only browser-owned termination and fresh target absence settle execution; renderer return, close acknowledgement and debugger detach alone cannot. Replaced/throwing close or a failed namespace/stop receipt keeps cleanup and the retained profile unsettled. Unrelated workers remain active. Creator scripts are quiesced and every reachable creator's confirmed original state is restored, including a caller's disabled scripts. The existing CDP command owner shares transient emulation observations with Playwright; failed, unobserved, detached or ambiguously ordered overrides supply no enabled default or erasure proof. Sessions are replaceable transport, never namespace authority. This adds no persisted worker ledger or model-facing debugger command.

State remains `ambit.browser-site-state.v1`: cookies, origin localStorage, structured IndexedDB values, generator provenance and explicit omissions. The old8MiB reader is a wire compatibility budget. The existing26 withheld secret tools remain withheld; this protocol adds no CLI/MCP command or model skill vocabulary. Product/HOST activation and identity isolation qualification are separate release gates; the service-held HOST probe is not exercised by the synthetic ordinary native/byte-consumer fixtures.

Chrome's origin-clear command clears its first-party storage key. Native cleanup also clears the actual A-origin storage keys observed in this owned profile, including A partitioned under B, without clearing B-origin keys. Those keys survive tab closure in the same retained-profile owner. Current frame/document receipts, not DOMStorage mutation events alone, settle key custody. New external profiles, an unobserved direct sign-in interval, event loss, and a new native process with no inventory continuity remain unknown and refuse import/clear before destructive work. This bounded checkpoint proves that refusal across an actual native process restart; it does not complete persistent site management. Recovery of full inventory/history after restart remains a required gate. The portable v1 capture/import represents first-party origin stores and does not claim partitioned localStorage/IndexedDB preservation.

W4 stores grant mode but does not claim W7 read-only effect enforcement. Exact-value redaction covers attached and captured scalar values and their plain, URL-encoded, base64 and hex spellings. Values shorter than eight bytes are matched as whole scalar values so a storage setting such as `a` or `true` does not erase ordinary prose. Protocol identifiers, sequencing and numeric geometry remain metadata; runtime by-value data is redacted recursively. This mechanism does not guarantee protection against arbitrary transformations or pixels in screenshots; HttpOnly cookies are additionally protected by the closed CDP boundary.
